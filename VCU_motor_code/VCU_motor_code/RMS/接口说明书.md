# 车辆驾驶画像模型 · 接口说明书

版本 v1.0 ｜ 交付形态：`portrait_core.pyd`（Windows 编译模块）

输入一段连续的国标时序放电片段，输出**驾驶风格画像 13 项 + 行驶工况画像 13 项**，共 26 项指标。模型参数已内置，无需任何配置文件。


## 2. 最简调用

```python
import pandas as pd
import portrait_core as pc

df = pd.read_parquet('one_segment.parquet')
df['ts'] = pd.to_datetime(df['ts'])

result = pc.predict(df, platform='BEV', battery_capacity_kwh=60)

if result['meta']['status'] != 'ok':
    print('数据异常：', result['meta']['abnormal_reason'])
else:
    print(result['driving_style_profile']['driving_style'])
    print(result['driving_scenario_profile']['driving_scenario'])
```

高频调用场景建议复用实例（避免重复初始化）：

```python
model = pc.VehiclePortraitModel()      # 进程内创建一次
for df in segments:
    r = model.predict(df, platform='BEV')
```

`predict` 无状态，可在多线程中并发调用。单次耗时约 15 ms。

## 3. 输入规范

### 3.1 数据结构

一个 pandas DataFrame，每行一帧，按时间升序。**建议 5 分钟窗口、10 秒采样、约 30 帧**。

输入字段分三档，按需提供即可。

#### ① 推荐字段（完整计算）

全部提供时，26 项指标完整输出，精度最佳。

| 字段 | 单位 / 取值 | 说明 |
|---|---|---|
| `ts` | datetime | 采集时间；字符串会被自动解析 |
| `speed` | km/h | 车速 |
| `voltage` | V | 动力电池总电压 |
| `current` | A | 总电流，**放电为正、回收为负** |
| `soc` | % | 0~100 |
| `accel_pedal` | % | 加速踏板行程 0~100 |
| `brake_pedal` | 0 / 1 | 制动踏板状态 |
| `motor_torque_nm` | N·m | 驱动电机转矩 |
| `motor_state` | 1/2/3/4 | 1 耗电、2 发电、3 关闭、4 准备 |
| `temp_max` | ℃ | 电池最高温度 |
| `temp_min` | ℃ | 电池最低温度 |

代码中可通过 `pc.RECOMMENDED_COLS` 取得该清单。
各字段的取值范围与枚举编码见 **3.2 字段取值详解**。

#### ② 极限可算字段（降级计算）

只提供以下 5 项也能出结果，缺失项对应的指标会降级：

```
ts, speed, current, voltage, soc
```

代码中为 `pc.MINIMAL_COLS`。缺少任一项则返回 `abnormal`，无法计算。

降级的具体表现：

| 缺失字段 | 影响 |
|---|---|
| `accel_pedal` | `pedal_smoothness_score` 返回 `None`；风格评分精度下降 |
| `temp_max` | 能耗基线按常温取值，能耗与续航类指标精度下降 |
| `brake_pedal`、`motor_torque_nm`、`motor_state`、`temp_min` | 当前版本无影响 |

每项缺失都会在 `meta.warnings` 中列明，其余指标照常输出。

#### ③ 备用字段（未来扩展）

以下字段当前版本不参与计算，**传入会被自动忽略**：

```
mileage, cell_max_v, cell_min_v, gear, motor_speed_rpm, vin, segment_id
```

代码中为 `pc.RESERVED_COLS`。除此之外的任何多余列同样被忽略，
**因此可以直接把原始宽表整体传入，无需预先筛选列**。

### 3.2 字段取值详解

本节逐字段说明取值含义、单位与合理范围。**枚举型字段的编码必须严格对齐**，
否则会导致指标失真或被判为异常。

#### 枚举型字段（固定取值）

**`gear` 挡位** —— 采用 GB/T 32960 编码（备用字段，当前版本不参与计算）

| 值 | 含义 | 说明 |
|---|---|---|
| `15` | P 驻车 | 车速恒为 0 |
| `14` | D 前进挡 | 正常行驶时的挡位 |
| `13` | R 倒挡 | 车速通常 < 5 km/h |
| `0` | N 空挡 | 车速为 0 |

若你的数据源使用其他编码（如厂商自定义的 `10=P, 11=R, 12=N, 13=D`，
或含制动/驱动力标志位的复合字节），需先映射到上表再传入。
复合字节取低 4 位即可：`gear & 0x0F`。

**`motor_state` 驱动电机状态** —— GB/T 32960 编码

| 值 | 含义 | 典型表现 |
|---|---|---|
| `1` | 耗电（驱动） | 总电流为正，车辆加速或匀速 |
| `2` | 发电（能量回收） | 总电流为负，制动或滑行 |
| `3` | 关闭 | 电机不工作 |
| `4` | 准备 | 上电待命 |

`254` / `255` 为国标定义的异常 / 无效值，传入会被自动置空。

**`brake_pedal` 制动踏板状态**

| 值 | 含义 |
|---|---|
| `0` | 未制动 |
| `1` | 制动中 |

统一为二值开关量。若你的数据源上报的是 `0~100` 的踏板行程百分比，
或国标里"只有开关量"时使用的转义码 `101`，请先归一化：**大于 0 即为 1**。
本模型不使用踏板深度信息。

#### 连续型字段（数值范围）

| 字段 | 单位 | 合理范围 | 越界处理 | 说明 |
|---|---|---|---|---|
| `ts` | — | — | 无法解析则报异常 | 采集时间，建议 10 秒间隔 |
| `speed` | km/h | 0 ~ 220 | 越界置空 | 车速 |
| `voltage` | V | 100 ~ 1000 | 越界置空 | 动力电池总电压 |
| `current` | A | −1000 ~ 1000 | 越界置空 | **放电为正、充电与能量回收为负** |
| `soc` | % | 0 ~ 100 | 越界置空 | 荷电状态 |
| `accel_pedal` | % | 0 ~ 100 | 越界置空 | 加速踏板行程 |
| `motor_torque_nm` | N·m | −1500 ~ 1500 | 越界置空 | 驱动电机转矩，负值为回收 |
| `temp_max` / `temp_min` | ℃ | −40 ~ 90 | 越界置空 | 电池最高 / 最低温度 |
| `motor_speed_rpm` | rpm | — | 不校验 | 电机转速（备用字段） |
| `cell_max_v` / `cell_min_v` | V | — | 不校验 | 单体最高 / 最低电压（备用字段） |
| `mileage` | km | — | 不校验 | 车辆累计里程（备用字段） |

**越界置空**指该帧的该字段置为缺失，其余帧不受影响；但若某个核心字段
（`speed` / `voltage` / `current` / `soc`）越界帧数超过 10%，会判为
`FIELD_OUT_OF_PHYSICAL_RANGE` —— 这通常意味着单位错误而非个别坏点。

#### 单位与量纲提醒

若上游以**定点整数**存储（常见于压缩存储的场景），务必先还原：

| 常见存储形式 | 还原方式 |
|---|---|
| 车速 ×10（如 `1152` 表示 115.2 km/h） | ÷ 10 |
| 电流 ×10（如 `634` 表示 63.4 A） | ÷ 10 |
| 转矩 ×10（如 `215` 表示 21.5 N·m） | ÷ 10 |
| 单体电压 ×1000（如 `3253` 表示 3.253 V） | ÷ 1000 |
| 电机转速偏移码（原始码 − 20000） | 减去偏移 |

未还原直接传入会触发 `FIELD_OUT_OF_PHYSICAL_RANGE`。

#### 一份合规输入示例

```
ts,speed,voltage,current,soc,accel_pedal,brake_pedal,motor_torque_nm,motor_state,temp_max,temp_min
2024-01-22 08:29:32,115.2,370.0,63.4,85.0,0.0,0,21.5,1,18.0,15.0
2024-01-22 08:29:42,114.9,370.0,72.3,85.0,2.0,0,22.0,1,18.0,15.0
2024-01-22 08:29:52,113.6,370.0,-18.5,85.0,0.0,1,-12.5,2,18.0,15.0
...共约 31 帧
```

第三帧是典型的能量回收状态：踏板松开、制动踏板置 1、电流与转矩转负、
`motor_state` 变为 `2`。

### 3.3 硬性约束

| 项 | 要求 | 不满足时 |
|---|---|---|
| 有效帧数 | ≥ 25 | `TOO_FEW_FRAMES` |
| 窗口时长 | ≥ 290 秒 | `WINDOW_TOO_SHORT` |
| 采样间隔中位数 | ≤ 60 秒 | `SAMPLING_TOO_SPARSE` |
| 片段性质 | 放电（驾驶）片段，不含充电 | `SOC_RISE_IN_DISCHARGE` 等 |

### 3.4 调用参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `df` | DataFrame | — | 片段数据 |
| `platform` | str | `'BEV'` | `'BEV'` 或 `'PHEV'`，影响能耗与续航基线 |
| `battery_capacity_kwh` | float | `None` | 电池额定容量；不传则 `scenario_range_baseline_km` 返回 `None` |

## 4. 输出规范

返回一个 dict，四个部分：

```python
{
  'window_summary':           {...},   # 窗口实测摘要 13 项
  'driving_style_profile':    {...},   # 映射表① 驾驶风格 13 项
  'driving_scenario_profile': {...},   # 映射表② 行驶工况 13 项
  'meta':                     {...},   # 状态与元信息
}
```

**调用方应先判断 `meta.status`**：为 `'abnormal'` 时三个 profile 均为 `None`。

### 4.1 window_summary 窗口实测摘要（13 项）

窗口内直接测得的统计量，不含任何模型推断，用于核对输入是否被正确解析。

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `frame_count` | int | 帧 | 参与计算的有效帧数 |
| `window_seconds` | float | 秒 | 窗口实际时长 |
| `avg_speed_kmh` | float | km/h | 平均车速（含怠速帧） |
| `max_speed_kmh` | float | km/h | 最高车速 |
| `speed_std_dev` | float | km/h | 车速标准差 |
| `idle_ratio_pct` | float | % | 怠速（车速为 0）帧占比 |
| `high_speed_ratio_pct` | float | % | 车速 >80 km/h 的帧占比 |
| `distance_km` | float | km | 行驶距离，由车速对时间梯形积分求得 |
| `energy_kwh` | float | kWh | 净消耗电量（放电减去回收） |
| `energy_per_100km` | float | kWh/100km | 实测百公里电耗 |
| `soc_start_pct` | float | % | 窗口起始 SOC |
| `soc_end_pct` | float | % | 窗口结束 SOC |
| `soc_drop_pct` | float | % | SOC 降幅，负值表示上升 |

与映射表指标的区别：本节全部是**实测值**，映射表里的
`window_avg_speed_kmh`、`window_distance_km`、`idle_ratio_pct` 等
与此处同名字段取值一致，属于为方便调用方而重复暴露。

`distance_km` 不依赖累计里程字段 —— 累计里程通常只有 1 km 分辨率，
在 5 分钟窗口尺度下相对误差过大，故一律采用车速积分。

### 4.2 映射表① 驾驶风格（13 项）

| 字段 | 类型 | 取值 |
|---|---|---|
| `driving_style` | str | conservative / normal / aggressive / very_aggressive |
| `style_confidence` | float | 0.0~1.0，分类置信度 |
| `aggressiveness_score` | int | 0~100，激进度综合评分 |
| `style_percentile` | str | "P0"~"P100"，同工况分位 |
| `hard_accel_rate` | float | 急加速频率，次/100km |
| `hard_decel_rate` | float | 急减速频率，次/100km |
| `accel_intensity_level` | str | low / medium / high |
| `braking_intensity_level` | str | gentle / moderate / harsh |
| `speed_stability_score` | int | 0~100，越高越平稳 |
| `pedal_smoothness_score` | int / None | 0~100；缺踏板数据时为 None |
| `regen_utilization_level` | str | low / medium / high |
| `energy_efficiency_rank` | str / None | A~E；窗口行驶距离过短时为 None |
| `eco_driving_score` | int / None | 0~100 |

### 4.3 映射表② 行驶工况（13 项）

| 字段 | 类型 | 取值 |
|---|---|---|
| `driving_scenario` | str | highway_cruise / elevated_cruise / urban_congested / urban_smooth / suburban |
| `scenario_confidence` | float | 0.0~1.0 |
| `congestion_level` | str | free_flow / light / moderate / heavy / jam |
| `road_type_estimate` | str | highway / expressway / arterial / urban_street / rural |
| `stop_go_frequency` | float | 启停频率，次/km |
| `idle_ratio_pct` | float | 怠速占比 0~100 |
| `high_speed_ratio_pct` | float | 车速 >80 km/h 占比 0~100 |
| `cruise_ratio_pct` | float | 巡航稳定段占比 0~100 |
| `scenario_energy_baseline` | float / None | 同工况基线能耗 kWh/100km |
| `scenario_range_baseline_km` | int / None | 同工况基线续航 km |
| `scenario_stability` | str | stable / transitioning / mixed |
| `window_avg_speed_kmh` | float | 窗口平均车速 |
| `window_distance_km` | float | 窗口行驶距离 |

`window_distance_km` 由车速对时间梯形积分求得，不依赖累计里程字段。

## 5. 异常识别

模型对不可信输入**不输出可疑指标**，而是返回异常状态。异常分四层，共 15 种码：

| 层 | `abnormal_code` | 触发条件 |
|---|---|---|
| 结构 | `EMPTY_INPUT` | 输入为空 |
| | `MISSING_REQUIRED_COLUMN` | 缺少极限可算字段中的某一项 |
| | `INVALID_TIMESTAMP` | 时间戳无法解析 |
| | `TOO_FEW_FRAMES` | 有效帧数 < 25 |
| | `WINDOW_TOO_SHORT` | 时长 < 290 秒 |
| | `SAMPLING_TOO_SPARSE` | 采样间隔中位数 > 60 秒 |
| 字段 | `CORE_FIELD_MOSTLY_INVALID` | 某核心字段有效率 < 70% |
| | `FIELD_OUT_OF_PHYSICAL_RANGE` | 某核心字段 >10% 的帧越界（多为单位错误） |
| 物理 | `NO_MOVEMENT` | 窗口内几乎无行驶 |
| | `SOC_RISE_IN_DISCHARGE` | SOC 上升 >2%，片段含充电 |
| | `ENERGY_DIRECTION_CONFLICT` | 行驶中净能量为负 |
| | `ACC_EXCEEDS_PHYSICAL_LIMIT` | >2% 的帧加速度超 4 m/s² |
| | `POWER_OUT_OF_RANGE` | 瞬时功率 P95 > 400 kW |
| | `ENERGY_OUT_OF_RANGE` | 百公里能耗超出物理可能范围 |
| | `SPEED_SIGNAL_STUCK` | 整段车速取值数 ≤2 且持续行驶 |
| 分布 | `DISTRIBUTION_OUTLIER` | 特征组合不符合正常驾驶数据的统计特征 |

处理建议：

```python
r = pc.predict(df, platform='BEV')
if r['meta']['status'] == 'abnormal':
    code = r['meta']['abnormal_code']
    if code in ('TOO_FEW_FRAMES', 'WINDOW_TOO_SHORT', 'SAMPLING_TOO_SPARSE'):
        pass    # 数据量不足，跳过该片段
    elif code in ('SOC_RISE_IN_DISCHARGE', 'ENERGY_DIRECTION_CONFLICT'):
        pass    # 片段切分有误，需检查上游放电片段提取逻辑
    elif code == 'FIELD_OUT_OF_PHYSICAL_RANGE':
        pass    # 检查字段单位与映射
    else:
        pass    # 记录日志，人工复核
```

## 7. 完整示例

```python
import pandas as pd
import portrait_core as pc

model = pc.VehiclePortraitModel()

def analyze(path, platform='BEV', capacity=60):
    df = pd.read_parquet(path)
    df['ts'] = pd.to_datetime(df['ts'])

    r = model.predict(df, platform=platform, battery_capacity_kwh=capacity)
    if r['meta']['status'] != 'ok':
        return {'ok': False, 'code': r['meta']['abnormal_code'],
                'reason': r['meta']['abnormal_reason']}

    s, sc = r['driving_style_profile'], r['driving_scenario_profile']
    return {
        'ok': True,
        'style': s['driving_style'],
        'score': s['aggressiveness_score'],
        'confidence': s['style_confidence'],
        'scenario': sc['driving_scenario'],
        'congestion': sc['congestion_level'],
        'distance_km': sc['window_distance_km'],
        'quality': r['meta']['data_quality_score'],
        'warnings': r['meta']['warnings'],
    }
```

## 8. 常见问题

**Q：导入时报 `ImportError: DLL load failed`**
Python 版本或位数不匹配。检查 `.pyd` 文件名里的版本号（`cp311` 对应 Python 3.11），并确认是 64 位 Python。

**Q：所有片段都返回 `FIELD_OUT_OF_PHYSICAL_RANGE`**
多为单位问题。若上游数据以定点整数存储（车速 ×10、电流 ×10），需先还原为物理量再传入。

**Q：`energy_efficiency_rank` 总是 `None`**
该指标要求窗口行驶距离 ≥ 0.3 km。极端拥堵片段（5 分钟只走一两百米）距离过短，
无法给出可信的能耗评价，会返回 `None`，属预期行为。

**Q：`motor_state` / `gear` 用的是别的编码怎么办**
需先映射到 3.2 节的标准编码。挡位若是含标志位的复合字节，取低 4 位
（`gear & 0x0F`）即可；制动踏板若是 0~100 行程或转义码 101，按"大于 0 即为 1"
归一化。编码不对齐会导致相关指标失真。

**Q：能否批量传入多个片段**
当前接口一次处理一个片段。批量请在调用方循环，复用同一个 `model` 实例。
