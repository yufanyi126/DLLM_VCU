# 车载远程控制 — 使用说明

## 架构概览

```
┌─────────────────────────┐         WebSocket          ┌─────────────────────────┐
│     电脑A（车载端）       │ ◄─────────────────────────► │    电脑B（远程上位机）    │
│                         │                             │                         │
│  car_server.py          │    data: 路段/车速/SOC/...   │  receive_demo.py        │
│    ↓ 调用                │    ◄────────────────────    │    ↓ AI 决策             │
│  main.py                │                             │    ai_decision()        │
│    ↓ 读取                │    control: engy_mode/      │                         │
│  GPS + CAN（模拟/真实）   │    ────────────────────►    │    下发控制命令           │
│                         │         dyn_mode             │                         │
└─────────────────────────┘                             └─────────────────────────┘
```

- **电脑A（车载端）**：运行 `car_server.py`，负责采集 GPS/CAN 数据，并通过 WebSocket 推送给上位机。
- **电脑B（上位机）**：运行 `receive_demo.py`，接收数据后运行 AI 决策，下发驾驶/能量模式控制命令。

---

## 一、`car_server.py` — 车载端 WebSocket 服务

### 作用

1. 调用 `main.init_session()` 初始化 GPS 传感器、CAN 设备、高德路线规划。
2. 循环调用 `main.step()` 采集实时数据。
3. 作为 WebSocket **服务端**（监听 `0.0.0.0:8765`），将每帧数据推送给连接的上位机。
4. 接收上位机下发的 `set_drv_mode` 控制命令，写入 CAN。

### 运行前需要修改的参数

在文件底部 `if __name__ == '__main__':` 块中：

```python
MY_PORT = 8765                               # WebSocket 监听端口，一般不用改
MY_ORIGIN = "106.830767,29.716379"           # 起点坐标 (lng,lat)
MY_DEST = "106.834505,29.715720"             # 终点坐标 (lng,lat)
```

| 参数 | 含义 | 示例 |
|------|------|------|
| `MY_PORT` | WebSocket 服务端口 | `8765` |
| `MY_ORIGIN` | 起点经纬度 | `"106.830767,29.716379"` |
| `MY_DEST` | 终点经纬度 | `"106.834505,29.715720"` |

### 间接依赖的配置（在 `main.py` 中）

这些参数影响 `car_server.py` 运行时的数据来源，**不需要改 `car_server.py` 本身**，但需要确认 `main.py` 中的设置是否符合预期：

| 配置项（main.py） | 默认值 | 含义 |
|-------------------|--------|------|
| `USE_NETWORK_GPS` | `True` | `True`=通过 TCP :9999 接收远程 GPS 数据；`False`=本机串口直连 GPS 传感器 |
| `MOCK_CAN` | `True` | `True`=无需硬件，模拟 CAN 信号；`False`=需要真实 CAN 盒 |
| `USE_CAN_TEST_TX` | `True` | 自动注入模拟 CAN 报文（调试用） |

### 运行方式

```bash
cd d:\MyPython\VCU_motor
python car_server.py
```

### 注意事项

- 需要先 `pip install websockets`
- 如果 `USE_NETWORK_GPS = True`，必须有其他程序往本机 `9999` 端口发送 GPS 数据（如 `gps_sender.py`），否则 `step()` 没有数据产出。
- 如果 `USE_NETWORK_GPS = False`，需要 GPS 传感器通过串口连接到电脑A。
- 如果没有任何 GPS 硬件，可以在 `main.py` 的 `step()` 中插入模拟 GPS 数据用于调试。

## 二、`receive_demo.py` — 远程上位机 AI 决策程序

### 作用

1. 通过 WebSocket **客户端**连接车载端 `car_server.py`。
2. 接收实时数据帧（车速、SOC、路况、驾驶模式等）。
3. 调用 `ai_decision()` 做 5 种策略判断。
4. 将控制命令下发回车载端。
5. 支持断线自动重连（3 秒间隔）。

### AI 决策策略
根据实际情况进行修改

| 触发条件 | 决策 |
|----------|------|
| SOC < 30% | EV + ECO（节电优先） |
| 车速 > 80 km/h | HEV + SPORT（高速动力） |
| 车速 < 30 km/h | EV + 标准（纯电经济） |
| 路况拥堵/缓行 | EV + ECO（启停省油） |
| 40 < 车速 ≤ 80 km/h | HEV + 标准（中速巡航） |

### 运行前需要修改的参数

在文件底部 `if __name__ == '__main__':` 块中：

```python
CAR_HOST = '10.194.1.183'   # 电脑A 的 IP 地址
CAR_PORT = 8765             # 电脑A 的 WebSocket 端口
```

| 参数 | 含义 | 如何获取 |
|------|------|----------|
| `CAR_HOST` | 电脑A 的 IP | 电脑A 终端执行 `ipconfig`，查看 IPv4 地址 |
| `CAR_PORT` | 电脑A 的端口 | 与 `car_server.py` 的 `MY_PORT` 保持一致 |

### 运行方式

```bash
cd d:\MyPython\VCU_motor
python receive_demo.py
```

### 注意事项

- 只依赖 `websockets`（`pip install websockets`），不依赖任何硬件。
- 不需要 `main.py` 或 CAN/GPS 相关的文件。
- 电脑B 和电脑A 必须网络互通。

## 三、完整调试步骤

### 前提

```bash
# 两台电脑都安装依赖
pip install websockets
```

### 电脑A（车载端）

```bash
# 步骤1：确认 main.py 中 GPS/CAN 配置正确
#        → 如果没有 GPS 硬件，确保 USE_NETWORK_GPS=True 且有数据源
#        → 或修改 main.py step() 插入模拟 GPS 数据

# 步骤2：启动车载服务
python car_server.py
```

看到以下输出表示就绪：

```
会话初始化完成.
[车端] 初始化完成，等待上位机连接...
[车端] WebSocket 服务启动: ws://0.0.0.0:8765
```

### 电脑B（上位机）

```bash
# 步骤1：修改 receive_demo.py 底部 CAR_HOST 为电脑A 的 IP

# 步骤2：启动上位机
python receive_demo.py
```

看到以下输出表示连接成功：

```
[上位机] 已连接到车载端
[上位机] 握手成功: 车端服务已就绪
```
